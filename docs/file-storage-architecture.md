# File storage architecture

`app.storage` owns the process-cached boto3 S3 client and all R2 operations. Signing uses AWS Signature Version 4, region `auto`, and bounded connection/read timeouts. `stored_files` contains metadata only, with private RFQ records referencing entity type and ID; it does not hold content or expiring URLs. Existing RFQ JSON metadata/local file behavior remains available when R2 is disabled. When R2 is enabled, new RFQ uploads use the private bucket and RFQ downloads retain the existing authorization check before redirecting to a short-lived signed URL. Private supplier rate import files use an R2 adapter behind the existing import storage contract.

Currently implemented routes: `POST /api/v1/files/upload-url`, `POST /api/v1/files/{file_id}/complete`, `GET /api/v1/files/{file_id}/download-url`, `DELETE /api/v1/files/{file_id}`, and `GET /api/v1/files/admin/summary`. Direct upload authorization currently supports RFQ attachments only. The existing RFQ multipart route is still the frontend-integrated flow. There is no public asset workflow, malware scanner, scheduled reconciliation job, quota service, or admin storage management screen yet.
