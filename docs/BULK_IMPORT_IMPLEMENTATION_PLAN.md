# Procura bulk import implementation plan

This plan is based on the current FastAPI, SQLAlchemy/Alembic, PostgreSQL, Next.js, and admin import code in this repository. It deliberately extends the existing catalog and supplier records rather than introducing parallel business tables.

## Existing implementation

- Material imports already have private staged uploads, a durable `ImportBatch` queue, a separate worker, preview/confirmation, 500-row application chunks, category/subcategory creation, source identity deduplication, validation reporting, and material search used by RFQs. Relevant code is in `backend/app/modules/imports/materials.py`, `backend/app/material_import_worker.py`, and the existing admin upload component.
- Supplier imports already reuse `Organization(source="imported")`, `Contact`, `ImportedSupplierTrade`, `ImportBatch`, and `ImportedRow`. Admin confirmation is explicit and imported contacts have `permission_to_notify=False`.
- Supplier import currently parses and confirms synchronously, supports XLSX and UTF-8 CSV (not legacy XLS), and makes the admin choose one eligible worksheet. Header aliases and continuation rows are limited. The client error download is a browser-generated CSV based on a bounded preview, not a complete server-side failed-row export.
- Supplier source trades are retained with `mapping_status="unreviewed"`; they are not converted into `Capability` records. The RFQ matcher requires verified suppliers and eligible exact category/city capabilities. This prevents unreviewed imported descriptions from causing irrelevant or unauthorized invitations.
- The existing dashboard already has Material Master, supplier import, category administration, and import history screens. Existing API contracts and material/category migrations should be retained.

## Target implementation

1. **Source inventory and baseline:** enumerate client workbooks and sheets, record file hashes and worksheet dimensions, inspect schema revision and read-only PostgreSQL counts, and take an approved backup/snapshot before any import. Do not treat anonymous runtime staging files as client files until their import-job metadata and source can be matched.
2. **Material ingestion:** retain the current durable material queue and identity strategy. Add legacy `.xls` parsing, import-all-eligible-worksheets support, aliases for client header variants, and confirm that unknown but valid units are preserved safely rather than making an administrator configure them manually. Keep descriptions intact and use the current `resolve_category` hierarchy and source identity. Persist source workbook, worksheet, and row provenance.
3. **Supplier ingestion:** move supplier workbook staging, parsing, and confirmation into durable background jobs using the existing `ImportBatch` staging fields and worker pattern. Process all selected/eligible worksheets in bounded chunks. Handle merged cells, carry-forward supplier names only when the row has supporting contact/trade data, preserve original phone/email strings, split multiple contacts without dropping source text, and mark ambiguous rows for review. Keep deterministic normalized-name/contact/trade deduplication and never overwrite registered organizations.
4. **Review and mapping:** expose imported trade rows and ambiguous supplier rows to admins with source workbook/sheet/row references. Allow explicit category mapping to existing taxonomy. Only a reviewed/approved capability with appropriate city and eligibility may participate in the current matcher; importing trade text alone must never create a capability or verified account.
5. **Admin import experience:** retain the existing dashboard and add supplier job progress, all-sheet selection, row-level preview, category mapping review, complete server-generated failed-row CSV, retry states, and import metrics/history. Escape spreadsheet formula-leading characters in every downloadable export.
6. **Schema and performance:** prefer existing `ImportBatch`, `ImportedRow`, `ImportedSupplierTrade`, `Contact`, `Organization`, `Category`, `Material`, and `Capability`. Add only provenance/review fields or indexes that are not already represented; ship changes with Alembic migrations and preserve existing RFQ snapshots and IDs.
7. **Validation:** add parser and database integration coverage for XLSX/XLS/CSV, all sheets, merged cells, continuation rows, international/Saudi phone preservation, malformed files, duplicates/reimports, category creation, contact grouping, import retry, search, RFQ matching policy, and quotation regression. Run against an isolated database first. Use read-only PostgreSQL counts and then an explicitly approved import against the intended target; report database-confirmed metrics only.
8. **Client population and readiness:** import the supplied files only after their inventory is confirmed, the preview is reviewed, and the target database and backups are verified. Verify counts, source traceability, searchable materials/suppliers, and the existing RFQ/quotation workflow. Do not send supplier invitations, create credentials, mark accounts verified, or claim successful population without database evidence.

## Current execution blockers

- No client workbooks are present as normal project files. There are 238 UUID-named XLSX files in private runtime staging; they cannot be attributed to a source workbook or import job without reading the configured PostgreSQL database.
- The configured database is remote PostgreSQL. A read-only inventory query was attempted, but the workspace network sandbox denied the connection. The escalated counts-only query did not return database results in this session.
- The database state, current Alembic revision, and staged workbook ownership therefore remain unverified. No migrations or production data writes have been run.
- In this implementation pass, confirmed supplier writes are background/batched, while supplier file parsing and preview still run in the upload request (8 MB, 30,000 rows per worksheet). XLS support depends on the new `xlrd` requirement, which is not installed in the current interpreter and could not be exercised here.
